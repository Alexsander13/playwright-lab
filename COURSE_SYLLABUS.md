# Программа курса Playwright Lab

## Цель и формат

Курс последовательно ведёт абсолютного новичка от запуска первого теста до портфельного проекта на Playwright Test и TypeScript. Все задания используют только `https://practice.expandtesting.com`: основной сквозной сценарий — Notes App и Notes API; специальные страницы этого же сайта — для лабораторных возможностей браузера.

В модулях 0–9 — **70 практических задач**. В базовой траектории — 59 задач; ещё 11 расширяют TypeScript, API-проверки, visual regression, мобильную эмуляцию, drag-and-drop и CI. Модуль 10 завершает курс чек-листом и не содержит самостоятельных задач или экзамена.

## Модуль 0. Начало проекта и первая автоматизация — 5 задач

0.1. **Вау-эффект.** Запустить готовый demo-тест: браузер открывается, выполняет вход и показывает конечную цель курса.

0.2. **Репозиторий.** Создать репозиторий из шаблона и клонировать его локально.

0.3. **Окружение.** Установить Node LTS, зависимости и браузеры Playwright; выполнить первый успешный `npx playwright test`.

0.4. **Конфигурация.** Создать `playwright.config.ts`; настроить `baseURL`, `testDir`, таймауты и скрипты `test`, `test:ui`, `test:debug`, `report`.

0.5. **Первый smoke-тест.** Открыть главную Expand Testing, проверить заголовок и создать первый осмысленный Git-коммит.

## Модуль 1. Основы TypeScript и первый UI-тест — 9 задач

1.1. **Первый UI-тест и поиск локатора.** Открыть Inspector, найти реальные элементы Web inputs по роли и доступному имени, затем подтвердить переход.

1.2. **Ввод текста.** Заполнить настоящую форму `/inputs` через `getByLabel` и проверить отображённое значение.

1.3. **Асинхронность.** Освоить `async`/`await` на API health-check.

1.4. **Параллельность запросов.** Применить `Promise.all` для независимых API-запросов и понять, почему он не подходит для действий в одном `page`.

1.5. **Конфигурация окружения.** Вынести URL в типизированный модуль окружения.

1.6. **Типы данных.** Описать интерфейс `TestUser` и применить его к генератору данных.

1.7. **Безопасность окружения.** Добавить `.env.example`, исключить `.env` из Git и валидировать отсутствующие параметры.

1.8. **Модели Notes API.** Описать DTO для пользователя и заметки.

1.9. **Generics и Utility Types.** Создать типизированную фабрику данных для Notes API.

## Модуль 2. Надёжные UI-тесты Notes App — 8 задач

2.1. **Первые локаторы.** Открыть Notes App и использовать `getByTestId` и `getByRole`.

2.2. **Устойчивость локаторов.** Сравнить role/test id с хрупкими CSS-селекторами и исправить намеренно сломанный тест.

2.3. **Регистрация через UI.** Создать уникального пользователя и проверить успешный результат.

2.4. **Авторизация.** Выполнить UI-логин и проверить доступные элементы навигации.

2.5. **Создание заметки.** Создать заметку и проверить title, description, category и state.

2.6. **Редактирование.** Изменить данные заметки и подтвердить сохранение.

2.7. **Жизненный цикл заметки.** Отметить заметку выполненной и удалить её.

2.8. **Поиск и фильтрация.** Найти заметку в UI и проверить изоляцию данных пользователя.

## Модуль 3. API: пользователи и заметки — 7 задач

3.1. **API health-check.** Проверить доступность Notes API сетевым запросом.

3.2. **Регистрация через API.** Отправить `POST /users/register`; проверить статус `201` и структуру ответа.

3.3. **API-логин.** Выполнить `POST /users/login`, извлечь и безопасно передать токен.

3.4. **API-клиент.** Спроектировать класс `UsersApi`, инкапсулирующий запросы.

3.5. **CRUD заметок: создание.** Создать заметку через API, проверить контракт и сохранить `id`.

3.6. **CRUD заметок: операции.** Реализовать list/get/update/complete/delete и негативные проверки `400`/`401`.

3.7. **Очистка данных.** Удалить тестовый аккаунт через API и подтвердить отсутствие тестового мусора.

## Модуль 4. Сквозные UI + API сценарии — 6 задач

4.1. **API-подготовка, UI-проверка.** Создать пользователя и заметку через API, затем найти заметку в интерфейсе.

4.2. **UI-создание, API-проверка.** Создать заметку в UI и проверить server-side state через API.

4.3. **Storage state.** Один раз авторизоваться через UI, сохранить browser state и повторно открыть Notes App без формы входа.

4.4. **Массовые данные.** Создать несколько записей через API и проверить выдачу поиска в UI.

4.5. **Смешанный lifecycle.** Подготовить заметку через API, удалить её в UI и подтвердить через API ответ `404` по сохранённому id.

4.6. **Теги.** Добавить `@smoke`, `@api`, `@ui`, `@e2e` и настроить выборочный запуск.

## Модуль 5. Архитектура, fixtures и данные — 9 задач

5.1. **LoginPage.** Выделить страницу логина в Page Object без избыточных абстракций.

5.2. **NotesPage и ProfilePage.** Разделить действия и assertions для заметок и профиля.

5.3. **Fixture пользователя.** Расширить `test` пользовательской fixture `registeredUser`.

5.4. **API-fixtures.** Добавить `apiClient` и `authenticatedApiClient`.

5.5. **Изоляция рантайма.** Внедрить `runId` и `workerIndex` для уникальных сущностей.

5.6. **Надёжный teardown.** Гарантированно очищать заметки и аккаунты даже при падении теста.

5.7. **Проверка состояния через Notes API.** Подтвердить серверное состояние без прямого доступа к БД.

5.8. **API-подготовка данных.** Создать данные через API и проверить их в UI.

5.9. **Расширенный cleanup.** Удалять заметки и аккаунт штатным API в `finally`.

## Модуль 6. Лаборатория возможностей Playwright — 8 задач

6.1. **Upload.** Загрузить файл через `setInputFiles`, проверить имя и очистить поле.

6.2. **Download.** Перехватить `download`, сохранить файл и проверить содержимое.

6.3. **Dialogs.** Обработать `alert`, `confirm` и `prompt` до действия-триггера.

6.4. **Iframes.** Работать с элементами фрейма через `frameLocator`.

6.5. **Popups и tabs.** Дождаться новой страницы через `context.waitForEvent('page')`.

6.6. **Shadow DOM.** Написать устойчивые локаторы для элементов Shadow DOM.

6.7. **Geolocation.** Настроить контекст с пользовательскими координатами и проверить UI.

6.8. **Network mocking.** Перехватить запросы через `page.route` и смоделировать ответы `200` и `500`.

6.9. **Visual regression.** Сравнить screenshot Notes App с осознанным baseline.

6.10. **Мобильная эмуляция.** Проверить Notes App в отдельном контексте iPhone.

6.11. **Drag-and-drop.** Выполнить перенос элементов на странице `/drag-and-drop`.

## Модуль 7. Нестабильность, диагностика и параллельность — 4 задачи

7.1. **Flaky tests.** Диагностировать нестабильную страницу без `waitForTimeout`.

7.2. **Артефакты падений.** Настроить `trace: 'on-first-retry'`, screenshots и video при падении.

7.3. **Параллельный запуск.** Запустить тесты в 2–4 worker и устранить конфликты данных.

7.4. **Полная параллельность.** Включить `fullyParallel` и настроить `maxFailures`.

## Модуль 8. Отчёты, CI и выпуск проекта — 7 задач

8.1. **HTML Report.** Настроить встроенный отчёт Playwright и локальный просмотр.

8.2. **Allure Report.** Подключить `allure-playwright`, оформить шаги и вложения.

8.3. **GitHub Actions: smoke.** Создать workflow с checkout, установкой Node и браузеров, запуском smoke-тестов.

8.4. **Nightly regression.** Настроить ночной запуск, `retries` и разделение ошибок.

8.5. **Sharding.** Разделить тесты между job и объединить blob-отчёты.

8.6. **Расширенный sharding.** Запустить три shard и объединить Allure-артефакты.

8.7. **CI Summary.** Вывести безопасную итоговую сводку в GitHub Actions без внешних мессенджеров.

## Модуль 9. AI-ассистенты в автоматизации — 4 задачи

9.1. **Локальный AI-инструмент.** Настроить OpenRouter и AI-расширение редактора, не раскрывая ключи.

9.2. **AI и локаторы.** Передавать минимальный безопасный фрагмент DOM для подбора устойчивого локатора.

9.3. **Custom Reporter.** Создать базовый репортёр Playwright, перехватывающий падения тестов.

9.4. **AI в пайплайне.** Дополнить репортёр безопасной отправкой ошибки в OpenRouter и выводом подсказки в консоль.

## Модуль 10. Wrap-up & Celebration

Финальный чек-лист готовности проекта для резюме, подведение итогов и завершение курса. Отдельных практических задач и формальной аттестации нет.
