

🗺️ Макро-программа курса: Все модули и задачи

**Ground Truth:** Playwright Lab — единый монорепозиторий платформы и контента. Полный курс создаётся последовательно, модуль за модулем, начиная с Модуля 0; прототипов и усечённых выборок нет. Утверждённые решения находятся в `PROJECT_GROUND_TRUTH.md`.

Текущий шаг — задача 0.1; после её завершения следующая по порядку — задача 0.2. Модули 0–9 включают 59 практических задач. Модуль 10 — финальное завершение курса без формальной аттестации.

Модуль 0. Начало проекта и первая автоматизация (5 задач)

⚬ Задача 0.1: «Вау-эффект» — запуск готового демо-теста, который самостоятельно открывает браузер, проходит логин и демонстрирует финальную цель курса.
⚬ Задача 0.2: Инициализация репозитория — создание GitHub-репозитория из шаблона и клонирование его на локальную машину.
⚬ Задача 0.3: Окружение и установка — установка Node LTS, зависимостей и бинарников браузеров Playwright, первый успешный запуск npx playwright test.
⚬ Задача 0.4: Конфигурация — создание playwright.config.ts, настройка baseURL, testDir, таймаутов и локальных npm-скриптов (test, test:ui, test:debug, report).
⚬ Задача 0.5: Первый smoke-тест — написание теста для главной страницы Expand Testing, проверка заголовка и оформление первого коммита.

Модуль 1. TypeScript, который нужен автоматизатору (6 задач)

⚬ Задача 1.1: Типизация сущностей — создание интерфейсов TestUser и Note.
⚬ Задача 1.2: Генерация данных — написание генератора уникального пользователя с использованием template literals.
⚬ Задача 1.3: Асинхронность — освоение async/await на примере API health-check.

⚬ Задача 1.5: Конфигурация окружения — перенос параметров URL в типизированный модуль окружения.
⚬ Задача 1.6: Безопасность переменных — добавление .env.example, исключение .env из Git и валидация отсутствующих параметров.

Модуль 2. Надёжные UI-тесты Notes App (8 задач)

⚬ Задача 2.1: Первые селекторы — открытие Notes App и написание теста с использованием getByTestId и getByRole.
⚬ Задача 2.2: Сравнение селекторов — анализ локаторов по ролям/test id против хрупких CSS-селекторов; исправление намеренно сломанного теста.
⚬ Задача 2.3: Регистрация через UI — создание уникального пользователя через интерфейс и проверка успешного состояния.
⚬ Задача 2.4: Авторизация — выполнение UI-логина и проверка доступных элементов навигации.
⚬ Задача 2.5: Создание заметки — создание сущности через UI, проверка title, description, category и state.
⚬ Задача 2.6: Редактирование — открытие заметки, изменение её данных и верификация сохранения.
⚬ Задача 2.7: Жизненный цикл заметки — отметка заметки как выполненной и её последующее удаление.
⚬ Задача 2.8: Поиск и фильтрация — поиск заметки в интерфейсе и проверка изоляции данных пользователя.

Модуль 3. API: пользователи и заметки (7 задач)

⚬ Задача 3.1: API Health-check — проверка доступности Notes API через сетевой запрос.
⚬ Задача 3.2: Регистрация через API — отправка POST /users/register, проверка статуса 201 и структуры ответа.
⚬ Задача 3.3: API Логин — выполнение POST /users/login, извлечение и безопасная передача токена.
⚬ Задача 3.4: Создание API-клиента — проектирование класса UsersApi для инкапсуляции запросов.
⚬ Задача 3.5: CRUD заметок (Создание) — создание заметки через API, проверка контракта и сохранение id.
⚬ Задача 3.6: CRUD заметок (Операции) — реализация list/get/update/complete/delete через API, негативные тесты на 400/401.
⚬ Задача 3.7: Очистка данных (Cleanup) — удаление тестового аккаунта через API и доказательство отсутствия «мусора».

Модуль 4. Сквозные UI + API сценарии (6 задач)

⚬ Задача 4.1: API-подготовка, UI-проверка — создание пользователя и заметки через API, открытие интерфейса и поиск заметки.
⚬ Задача 4.2: UI-создание, API-проверка — создание заметки в интерфейсе, запрос бэкенда через API и верификация server-side state.
⚬ Задача 4.3: Storage State — логин в UI с помощью сохраненного storage state, полученного через API.
⚬ Задача 4.4: Массовые данные — генерация нескольких записей через API и проверка поисковой выдачи в UI.
⚬ Задача 4.5: Смешанный lifecycle — удаление заметки через интерфейс и подтверждение 404 ошибки через API.
⚬ Задача 4.6: Тегирование — добавление тегов @smoke, @api, @ui, @e2e и настройка выборочного запуска.

⚬ Задача 6.6: Shadow DOM — написание устойчивых локаторов для элементов внутри Shadow DOM.
⚬ Задача 6.7: Geolocation — настройка контекста браузера с кастомными координатами и проверка UI.

Модуль 7. Нестабильность, диагностика и параллельность (4 задачи)

⚬ Задача 7.1: Борьба с flaky tests — диагностика нестабильной страницы и отказ от использования waitForTimeout.
⚬ Задача 7.2: Артефакты падений — настройка trace: on-first-retry, сохранение скриншотов и видео при падении.
⚬ Задача 7.3: Параллельный запуск — запуск тестов в 2–4 воркера, устранение конфликтов данных.
⚬ Задача 7.4: Полная параллельность — включение fullyParallel и настройка параметра maxFailures.
