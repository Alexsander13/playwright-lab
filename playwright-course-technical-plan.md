1. Итоговое решение

Тестируемая система (SUT) — Expand Testing. Это единственный внешний домен курса.

В качестве сквозного приложения выбран Notes App вместе с его Notes API. Ученик автоматизирует пользовательский сценарий работы с заметками: регистрация, вход, создание, поиск, чтение, редактирование, завершение, удаление заметок, профиль и выход.

Остальные страницы того же домена используются только как лаборатории для возможностей браузера, которых нет в Notes App: iframe, download/upload, popup, dialog, Shadow DOM, drag-and-drop, геолокация, динамические таблицы, HTTP-статусы, нестабильный DOM и сетевые задержки. Это не отдельные продукты и не отдельные репозитории.

Почему не создавать собственное приложение

Создание учебного магазина или CRM одновременно с курсом удваивает продуктовую работу: нужно поддерживать frontend, backend, БД, учётные записи, деплой, безопасность и тестовые данные. Ценность Playwright Lab создаёт качественный путь обучения и проверка работ ученика, а не ещё один демо-продукт.

Expand Testing уже позиционируется как площадка для UI и REST API automation, содержит современное React-приложение и большой набор специализированных упражнений. Один домен снижает число переменных: единый BASE_URL, единый список разрешённых URL для CI, один набор Page Objects и одна история в README финального репозитория.

2. Результаты технического исследования (28 сентября 2026)

Подтверждённая связность Notes App и API

⚬ Swagger Notes API версии 2.0.0 прямо указывает, что API служит backend для Notes App.
⚬ UI загружает API-базу [https://practice.expandtesting.com/notes/api](https://practice.expandtesting.com/notes/api).
⚬ UI вызывает POST /users/login, хранит токен в localStorage и передаёт его в заголовке x-auth-token.
⚬ UI вызывает GET/POST /notes, GET/PUT/PATCH/DELETE /notes/{id}. Следовательно, сценарий «создать сущность API → убедиться в UI» является реальным, а не искусственно склеенным.
⚬ В UI присутствуют стабильные data-testid для ключевых действий, включая навигацию, логин и работу с заметками.

Вывод исследования

Notes App + Notes API достаточно богаты для основного портфельного проекта. Он поддерживает настоящие auth и CRUD-данные, а не только статические демонстрации. Остальные возможности Playwright можно закрыть внутри того же домена. От трёх независимых внешних сервисов следует отказаться.

3. Ограничения выбранного SUT и защита от них

Мы не контролируем uptime, DOM и API-контракт. Один сервис уменьшает риск каскадного отказа, но не делает его нулевым.

Меры:

1. Все адреса централизованы в `src/config/env.ts`: `BASE_URL` для UI и `NOTES_API_URL` для Notes API. Другие адреса выводятся из этих значений; дополнительные URL-переменные запрещены.
2. Перед основным прогоном CI выполняется лёгкий API health-check. При недоступности сервисов статус должен быть понятным: инфраструктурная ошибка, а не «упал тест логина».
3. Каждая задача фиксирует ожидаемую версию/состояние сценария и проверяется регулярным мониторингом курса.
4. Нет общих заранее созданных аккаунтов. Каждый запуск генерирует уникальный e-mail с UUID/worker index, регистрирует пользователя и удаляет аккаунт в afterAll или cleanup job.
5. Задания про network mocking не зависят от доступности API после загрузки страницы: ответ перехватывается локально через page.route.
6. При критическом изменении домена адаптер сосредоточен в src/config и src/clients, а не размазан по урокам.
7. Недоступность SUT диагностируется отдельно от ошибки функционального сценария. Локальные моки применяются в задачах по network mocking и не заменяют основной SUT.

При отправке отчёта в OpenRouter разрешены только текст ошибки, stack trace и минимальный DOM-фрагмент упавшего локатора. До отправки исключаются пароли, персональные данные, токены (включая `x-auth-token`) и чувствительные значения окружения. Полный DOM, заголовки запросов и дампы окружения запрещены.

Стратегия проверки работ

CLI-проверка курса через `npm run verify` с синхронизацией прогресса через Supabase.

⚬ Ученик работает в локальном GitHub-репозитории.

Проверку развивать параллельно с учебным контентом, начиная с Модуля 0.
