# Course Authoring Guidelines (Playwright Lab)

## 0. Источник истины и последовательность
- Утверждённые решения и текущий статус брать из `PROJECT_GROUND_TRUTH.md`.
- Создавать полный курс последовательно, модуль за модулем, начиная с Модуля 0; не планировать прототипы или усечённые выборки.
- Сейчас начата задача 0.1; следующая — задача 0.2 после завершения 0.1.
- Модули 0–9 включают 59 практических задач. Модуль 10 — финальное завершение курса без формальной аттестации и дополнительных задач.
- Параллельно с контентом развивать CLI-проверку `npm run verify` и синхронизацию прогресса с Supabase.

## 1. Основные принципы обучения
- **Обучение через задачи:** урок — это инженерный результат, а не лекция. Каждая задача должна приводить к видимому и проверяемому изменению в Git-репозитории ученика.
- **Не сводить урок к копированию:** не предлагать просто скопировать блок кода. Объяснять, почему выбрано архитектурное решение и какую проблему оно решает.
- **Постепенное раскрытие сложности:** вводить новые концепции поэтапно. Не вводить Page Objects, fixtures и сложный mocking до того, как ученик столкнётся с неудобством дублирования.

## 2. Структура урока или задачи
При создании и проверке задач модулей 0–9 всегда использовать эту структуру:
1. **Контекст и проблема:** какую реальную инженерную задачу решаем?
2. **Краткая теория:** только понятия, необходимые на текущем шаге.
3. **Стартовое состояние и изменения файлов:** точный список файлов для изменения.
4. **Критерии готовности (DoD):** ясные функциональные и технические критерии приёмки.
5. **Подсказки (3 уровня):** направление мысли → ссылка на API → целевой фрагмент кода. На уровнях 1–2 не давать готовое решение целиком.
6. **Git-чекпоинт:** ожидаемый формат сообщения коммита, например `feat(ui): ...`.

## 3. Ограничения тестируемой системы (SUT)
- Использовать единственную SUT — **Expand Testing / Notes App & API** — через переменные окружения `BASE_URL` и `NOTES_API_URL`. Не добавлять сторонние тестируемые сервисы.
- Централизовать конфигурацию URL в `src/config/env.ts`; не добавлять другие переменные окружения для адресов SUT. Дополнительные endpoints выводить из `BASE_URL` или `NOTES_API_URL`.

## 4. Безопасность данных AI-репортера
- В OpenRouter разрешено отправлять только текст ошибки, stack trace и минимальный фрагмент DOM, относящийся к упавшему локатору.
- До отправки удалять пароли, персональные данные, токены авторизации (включая `x-auth-token`) и чувствительные значения окружения.
- Не отправлять полный снимок DOM, заголовки запросов или дампы окружения.

## 5. Особенность задачи 0.1
- Задача 0.1 — вводная демонстрация; коммит для неё явно не требуется. Не добавлять к ней стандартный Git-чекпоинт.
- Переходить к задаче 0.2 только после завершения 0.1, сохраняя заданный порядок модуля.
